# Your skill name

One line on the job and who judges the result.

## Read first

Read these in full before anything else, every time:

1. path/to/project-rules.md: the rules for this project.
2. path/to/voice-or-brand.md: the voice, brand or style this output must match.
3. path/to/examples.md: worked examples of a finished output.

## Hard rules

These hold in every mode. Each one names the failure it prevents.

1. Never invent a fact, number, name or quote. If one is missing, write [ADD: what is needed] and ask.
2. Rule two.
3. Rule three.

When rules conflict: hard rules, then facts, then voice, then platform, then pattern lists.

## Workflow

1. Read the whole source before planning.
2. Step two, with the exact command if there is one.
3. Step three.
4. Run the gates below. Fix every failure before going on.

## Gates

Each gate is pass or fail.

- Facts: every number and quote traces to the source.
- Tells: none of the banned patterns in path/to/patterns.md.
- Review: an independent reviewer returns PASS. Stop and ask after three failed rounds with no progress.
- Approval: a human approves before anything is exported or posted.

## Deliverable

- Files: name_vN_<start>_to_<end>.ext, full absolute paths.
- Summary: under five lines. What changed, where it is, the one decision needed, recommended option first.

## Retro

- Feedback stated as a rule ("never", "always", "from now on") becomes a rule now, in the one file it belongs to.
- Feedback about a single line is logged as an observation; a second matching one promotes it to a rule.
- Commit the rule file so the next session reads it.
